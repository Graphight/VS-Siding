# Sectioned mode picker

- Status: Draft
- Created: 2026-09-25
- Reflects: decisions 0017, 0022, 0027, 0031; `PlaceWallFrame.cs`; `SidingWallBlock.cs`; `wall.json`'s `planks-{wood}`/`shakes-{wood}` entries; `WallShapeGen.cs`; decompiled 1.22.7 `GuiDialogToolMode`, `GuiElementSkillItemGrid`

## Summary
The saw's mode picker becomes rows of toggles: a framing row (wall, corner), a boards row (weatherboard, boards) and a logs row (shakes, logs).
Each row holds its own choice, a finish row can hold none, and "none" keeps today's face default.
The choices are stored on the player, not the item stack, so the picker reads the same whatever is in hand, and logs gain the style choice planks got in decision 0027.

## Context
**Today's picker is one flat list of verbs.**
`PlaceWallFrame` (`PlaceWallFrame.cs:33-39`) offers `wall`, `corner`, `weatherboard`, `boards`, and stores the pick as one `toolMode` int on the plank stack (line 50).
Modes 2 and 3 frame nothing and only finish (`SidingWallBlock.ResolveLayout`, line 921), so a player switches away from framing to pick a board style and back again to frame.
Two stacks of the same planks can sit in different modes.

**Logs have no picker at all.**
The finish entry comes from the held item (`MatchConsumes(heldCode, ...)`, `SidingWallBlock.cs:308`), and a held log carries no siding behaviour, so a shake finish always lands as `front-shakes` on the front and `back-logs` on the back (`wall.json`'s `shakes-{wood}`, no `Styles` key).
0027 deferred this for exactly that reason.

**What vanilla's picker can draw.**
`GuiDialogToolMode` (`GuiDialogToolMode.cs:60-110`) starts a new row at every `SkillItem` with `Linebreak`, so rows come free.
It draws no headings, and each option's name shows on hover.
`GuiElementSkillItemGrid` ignores `SkillItem.Enabled`, so dimming is ours to draw; `GetToolModes` is asked each time the dialog opens, so it can hand back dimmed icons for the unselected options.
A click reaches `SetToolMode` as one flat index, which the behaviour maps back to a row and an option.

## Design
**Rows.**
Framing: `wall`, `corner`.
Boards: `weatherboard`, `boards`.
Logs: `shakes`, `logs`.
A later finish family adds a row.

**One choice per row.**
Framing always has one, defaulting to `wall`.
A finish row has at most one: clicking its lit option turns it off, and a row with nothing lit uses the entry's `Elements` default, weatherboard or shakes on the front and boards or logs on the back.
The selected option draws white, the others in the row draw dimmed: each icon is loaded twice through `LoadSvgWithPadding` (0031), once tinted white and once grey.

**Stored per character.**
The three choices live in the player entity's `WatchedAttributes`, set in `SetToolMode`, which vanilla runs on both sides, and synced to the client with the entity.
Old `toolMode` ints on plank stacks are ignored, so a stack left in corner mode comes back in wall mode.

**The picker is its own behaviour.**
A new `CollectibleBehavior` carries `GetToolModes`/`SetToolMode` and is patched onto planks and placed logs.
`PlaceWallFrame` keeps placement only, on planks only.

**Modes stop being verbs.**
A saw-in-offhand click decides what to do from what it hits, as 0027's default already does: a finishable face gets the held material's finish, anything else gets a frame.
The finish uses its row's choice, or the face default when the row is empty; the frame uses the framing row.
So 0027's "a style mode frames nothing" rule and its `build-needs-infill` refusal for style modes go away.
Restyling in place (0027) carries over: a finished face clicked with the same material and a different lit style restyles for free.

**Log geometry.**
Two new groups mirror the existing pair: `front-logs` from `back-logs`' boxes, and `back-shakes` from `front-shakes`' relief (0022), plus `secondfront-logs` for `cornerout`.
All generated by `WallShapeGen` and `just shapes`, named `{face}-{style}` as 0027 set out, so `SelectiveElements` needs no change.
`shakes-{wood}` gains `Styles: ["shakes", "logs"]`, with two new icons.

## Alternatives considered
- **A second flat picker on logs, modes 4 and 5.** The smallest change, but it keeps the verb-style modes and stacks that disagree.
- **Headings or collapsible rows.** Needs our own dialog replacing vanilla's; the picker is small enough that rows and hover names are enough.
- **Per-stack storage.** Two stacks of oak planks could disagree, and the logs row would live on a different stack from the boards row.

## Consequences & open questions
- Every plank and placed log in the game shows the picker while held, saw or not, as planks already do.
- `back-shakes` inherits 0022's 96-row relief table; `front-logs` is cheap.
- Open: whether the picker should show only the rows that apply to the held item, or always all three.

## Stages
1. **Picker:** the new behaviour with rows, per-row choices in `WatchedAttributes`, dimmed icons, patched onto planks and logs; `PlaceWallFrame` reads the framing row.
2. **Click semantics:** `SidingWallBlock` reads the row for the held finish instead of `ResolveStyle(toolMode)`, and drops the style-mode refusals.
3. **Log geometry:** `front-logs`, `back-shakes`, `secondfront-logs`, `Styles` on `shakes-{wood}`, two icons.
4. **Playtest:** both faces of a partition in each style and none, both `cornerout` legs, restyling in place, switching held items with the picker open.
5. **Graduate** as a decision superseding 0027's style modes.
